# Android CI reproducibility note (2026-11-06)

The workflow pins Flutter 3.47.9 and pre-installs the corresponding NDK 28.2.13676358 with validation and up to 3 retries. On 2026-11-05 an Android GitHub Actions build failed when the SDK manager downloaded a corrupt NDK archive (error reading ZIP from SeekableByteChannel). The code analyzer and widget tests passed, and a previous PR debug build had passed. This change makes the transient dependency download recoverable.

Whenever Flutter is intentionally upgraded, update **both** the pinned Flutter version and, after reviewing generated `android/app/build.gradle.kts`, the required NDK version in the workflow. Preserve exact version numbers in source control. Native runner templates are currently generated by Flutter and will be committed once package/bundle identifiers are client-approved.

If the build still fails after retries: inspect GitHub Actions Android build logs and the remote SDK repository; do not simply retry repeatedly or claim a new APK exists. No production signing credentials are required for a debug build.
